# stock5-0 종목 공유 기록

## 현재 버전 사용법

- 엑셀 `검색 결과`의 글자색도 화면 표와 동일하게 저장합니다. 종목명은 파란색, 종목 코드·통화는 회색, 돌파·양전환 및 해당 괴리율은 빨간색, 붕괴·음전환 및 해당 괴리율은 파란색입니다. 괴리율이 0%라도 화면의 신호 색상을 유지합니다. 일반 글자와 표 제목의 색상도 저장 버튼을 누르는 시점의 화면 색상을 사용합니다.

- 6번·7번의 `엑셀 저장`은 현재 일/주·시장·방향·종목명/코드 필터에 맞는 **모든 페이지**의 결과를 `.xlsx`로 접속한 기기에 바로 다운로드합니다. 추가 서버 요청이나 엑셀 파일의 서버 저장/업로드는 없으며 기존 백그라운드 검색 진행 저장은 그대로 유지합니다. 파일명에 검색 종류·봉 단위·시장·방향·검색어 일부·최근 거래일 범위·검색 상태·저장 시각(KST)을 표시합니다. `저장 요약` 시트에 전체 검색어·필터·결과 수·검색 상태/진행률·자료 갱신 시각·시장별 비교 거래일/주 시작일·목록 출처·제외 건수·오류를 넣고, `검색 결과` 시트에 전체 종목명과 코드·통화·비교 가격/이평 또는 전환 기준가·괴리율을 넣습니다. 진행 중/일부 미완료/이전 자료 및 결과 0건도 해당 상태를 명시해 저장할 수 있습니다. 가격·날짜·비율은 실제 숫자형이며 종목 코드는 문자로 유지하고, 결과 제목 행과 종목명/코드 열은 고정됩니다. 차트 이미지는 포함하지 않습니다.

- 처음 접속하면 기존 서버 비밀번호로 로그인합니다. 저장된 비밀번호가 유효하면 다음 접속 시 자동 로그인하며, 헤더의 별도 기록 연결 버튼은 없습니다.
- 로그인할 때 저장된 종목 기록을 불러오고, 이후 기록 버튼 변경은 별도 저장 버튼 없이 서버에 자동 저장합니다.
- Top 100 / 니케이 Top 50 종목명 앞에는 시가총액 순위가 `1. 삼성전자`처럼 표시됩니다. 해외는 갱신된 대형주 후보군을 공식 NASDAQ/JPX 상장 목록과 대조한 뒤 전일 종가 기준 추정 시가총액으로 정렬합니다(전체 시장의 확정 순위가 아닙니다). 카드에서 다른 종목을 검색하면 원래 종목의 순위는 표시하지 않습니다.
- 해외 시세는 동시 3개까지만 조회하고, 상장폐지된 NTT DATA(9613.T), WBA 및 잘못된 나스닥 코드를 후보에서 제거했습니다. 개별 조회 실패 시 다른 후보로 100/50개를 채우되, 부족하면 조회된 차트부터 표시하고 누락 안내/재조회 버튼을 제공합니다. 일부 후보가 빠진 순위는 안내에 명시하며 49개 때문에 전체 화면이 차단되지 않습니다. 이전 후보군으로 저장된 해외 순위 캐시는 새 버전에서 다시 생성합니다.
- 캔들 레전드 아래 한 줄에 PER / F.PER / ROE / F.ROE / PBR / PEG / 시총 / 매출 / 영업이익을 표시합니다. 좁은 화면에서는 줄바꿈 없이 해당 줄만 가로 스크롤합니다.
- 시총·매출·영업이익은 절댓값 기준 100조 초과는 정수, 1조 초과~100조 이하는 소수점 최대 1자리, 1조 이하는 최대 2자리로 반올림합니다.
- `6. 200이평 돌파/붕괴`는 Top 목록에 제한하지 않고 KOSPI·KOSDAQ 전체, NASDAQ 상장주식, 도쿄 Prime·Standard·Growth 전체 주식을 검색합니다. NASDAQ ETF·테스트·워런트·유닛·권리·채권, 도쿄 ETF·ETN·REIT·PRO 및 도쿄 외 거래소는 대상이 아닙니다. 국내 목록은 네이버의 전체 주식 목록, NASDAQ은 Nasdaq Trader 공식 목록, 일본은 JPX의 최근 월말 공식 목록을 사용합니다. 목록 조회 실패 때 Top 종목으로 대체하지 않습니다.
- `일`은 시장 지수의 실제 최근 두 거래일, `주`는 최근 두 주봉을 비교합니다. 각 기간의 종가와 해당 기간까지의 200개 종가 단순평균을 비교하며, 돌파는 이전 ≤ 이평 / 최근 ≥ 이평, 붕괴는 반대입니다. 두 기간 모두 이평과 같으면 제외합니다. 주봉은 일봉을 월요일 시작 주별로 묶은 마지막 종가 기준입니다. 최근 주봉은 진행 중일 수 있고, 장중 값으로 계산한 신호는 바뀔 수 있습니다.
- 검색 결과 표는 내부 가로·세로 스크롤을 사용하며, 항목 제목 행과 종목명 열이 고정됩니다. 종목명에는 최대 15자(말줄임표 포함) 공간만 배정하고, 전체 이름은 마우스를 올리거나 차트 팝업을 열어 확인합니다.
- 일봉으로 묶은 주봉이 201개 미만이면 해당 종목만 실제 주봉 최대 300개를 추가 조회합니다. 최근 두 주의 종가·거래일은 원래 일봉 스냅샷을 유지하고, 더 오래된 주봉을 보완해 계산합니다. 추가 조회 후에도 실제 자료가 201주 미만이면 제외합니다(신규 상장 또는 제공 자료 부족). 조회 실패는 이력 부족으로 표시하지 않고 별도 오류로 표시하며, 연속 5회 통신 오류 시 해당 시장의 주봉 추가 조회만 중단하고 일봉 검색은 계속합니다. 기존 검색 파일은 같은 거래일일 때 이전 주봉 이력 부족 항목만 재검사합니다.
- 200이평 검색 결과의 종목명을 누르면 KOSPI100과 동일한 기존 차트 컴포넌트(캔들·거래량·MACD·일목균형표)가 팝업에 표시됩니다. 그래프 폭은 같은 화면의 KOSPI100 한 종목 카드 폭과 맞추며, 팝업 내부 세로 스크롤로 네 차트를 모두 봅니다. 200이평·BB 레전드·추세선·재무정보·롱/숏/주의 기록 등 기존 기능을 유지하고, 주 단위 결과는 주봉으로 시작합니다. 우측 위 고정 `X` 또는 `Esc`로 닫으면 차트 갱신을 종료하고 검색 결과로 돌아갑니다.
- `7. 삼선전환도`는 6번과 같은 전체 시장에서 일·주 단위의 최근 봉에 새로 발생한 양전환·음전환을 검색합니다. 종가로 전환선을 생성하고, 음선 상태에서 최근 생성된 전환선 3개 범위의 최고가를 초과하면 양전환, 양선 상태에서 최저가 미만이면 음전환입니다. 일반 캔들 3개를 비교하는 방식이 아닙니다. 같은 방향의 연장, 기준가와 같음, 지난 봉에서 발생한 전환은 최신 전환으로 표시하지 않습니다. 전환선 3개를 만들지 못하면 전환선 부족으로 제외합니다. 계산은 확보된 일봉 최대 1,250개 및 주봉 보완 자료를 시작점으로 하며, 최근 주봉은 진행 중일 수 있습니다. 기준: [TradingView 삼선전환도 계산 설명](https://www.tradingview.com/support/solutions/43000502273-introduction-to-line-break-charts/).
- 6번·7번은 한 백그라운드 작업과 조회 자료·동시 조회 제한(최대 2종목)을 공유합니다. 메뉴·일/주 전환으로 중복 전체 검색을 만들지 않습니다. 기존 6번 검색 파일에 삼선전환 계산이 없으면 7번을 처음 열 때 누락 종목만 다시 조회하고 이후에는 같은 저장 결과를 재사용합니다. 7번도 양전환/음전환·시장·종목명 필터, 고정 제목 행·15자 종목명 열, 동일한 종목 차트 팝업을 지원합니다.
- 헤더 `삼선` 버튼은 [stock5-8](https://github.com/ddubii00/ddubii00-stock5-8)의 삼선 모드와 같이 메인 캔들을 종가 기준 삼선전환도로 표시하고, 다시 누르면 원래 캔들·MACD로 복원합니다. 거래량은 전환선이 생성될 때까지 원본 봉의 거래량을 합산하고 미확정 거래량은 다음 선까지 기다립니다. MA·BB는 생성된 전환선 종가 기준이며 계산에 필요한 선이 부족한 값은 임의로 채우지 않습니다. 일목균형표는 원래 OHLC를 유지하고 MACD 영역은 삼선 모드에서 빈 영역으로 유지합니다. 전환 시 이미 받은 원본 시세를 재사용하여 추가 REST 요청 없이 그리며, 일·주·분·월 선택 및 검색 결과 차트 팝업에도 적용됩니다. 삼선 추세선은 일반 캔들 추세선과 별도로 저장합니다.
- 최초 전체 검색은 오래 걸릴 수 있습니다. Oracle 서버에서 최대 2종목씩 백그라운드 검색하고, 화면은 15초 REST로 진행률·발견 목록만 받아옵니다. 일/주 전환은 같은 검색 자료를 사용하므로 다시 전 종목을 조회하지 않습니다. 이력 부족(두 MA 계산에 201봉 필요)·최신 날짜 불일치·조회 실패는 제외 건수와 사유를 표시합니다. 5회 연속 자료 조회 실패한 시장은 중단하고 오류를 표시합니다.
- 검색 진행은 `data/stock5-0-ma200-scan.json`(또는 `STOCK5_DATA_DIR`)에 따로 저장하며 기존 종목 기록 파일을 변경하지 않습니다. 메뉴 이동·브라우저 종료 뒤에도 서버 검색은 계속됩니다. 서버 재시작 후에는 같은 기준 거래일의 중단된 검색을 이어갑니다. 완료 검색은 15분 동안 재사용하며 `새로 검색`으로 갱신할 수 있습니다. 검색은 최초 조회 시점의 시장 거래일에 고정되고 각 종목의 조회 시점은 다를 수 있습니다. 전체 백그라운드 검색은 Vercel 서버리스가 아닌 Oracle 상시 서버용입니다.
- 금액은 각 제공 통화의 조 단위이며, 국내는 조원, 해외는 조USD·조JPY 등으로 표시합니다. 국내 실적은 최근 확정 연간, 예상은 다음 제공 연간 컨센서스이며 해외 매출·영업이익은 TTM 기준입니다. 미제공 값은 `—`, 예상 EPS 성장률로 계산한 국내 `PEG*`와 해외 마진 기반 `영업이익*`는 추정값입니다. 각 값에 마우스를 대면 기준을 확인할 수 있습니다.
- 재무정보는 종목별 6시간 캐시·최대 2종목 동시 조회를 사용합니다. 차트의 기존 15초 REST 갱신은 유지하며 재무정보는 15초마다 요청하지 않습니다.
- KOSPI100 / KOSDAQ100 / NASDAQ100 / 니케이 Top 50의 종목 카드에 `롱 보유`, `롱 관심`, `숏 관심`, `숏 보유`, `주의!` 버튼이 표시됩니다.
- 네 가지 롱·숏 상태는 한 번에 하나만 선택됩니다. 활성화된 버튼을 다시 누르면 해제됩니다.
- `주의!`는 기본 **꺼짐**입니다. 누르면 노란색으로 켜지고, 다시 누르면 꺼집니다. 롱·숏 상태와 독립적으로 저장됩니다.
- 기록은 브라우저가 아니라 서버에 저장됩니다. 다른 컴퓨터에서도 같은 서버 비밀번호로 연결하면 기록이 보이며, 15초마다 또는 창에 다시 포커스할 때 갱신됩니다.
- 기존 분류와 평균가 데이터는 유지됩니다. 상태 변경은 해당 종목의 변경된 필드만 저장하므로 다른 기기에서 저장한 종목을 덮어쓰지 않습니다.
- Oracle은 기본 `data/stock5-0-state.json`을 사용합니다. `STOCK5_DATA_DIR`로 영구 저장 경로를 지정할 수 있습니다. 업데이트할 때 기존 `data/`를 삭제하지 마세요.
- 서버리스 배포는 영구 공유 저장을 위해 `KV_REST_API_URL`, `KV_REST_API_TOKEN`을 함께 설정해야 합니다.

이 기능은 이미 소스에 적용되어 있습니다. 최신 소스를 가져와 빌드하고 서비스를 재시작하면 됩니다. 아래의 예전 `apply-stock5-0-*.mjs` 패치 절차를 다시 실행하지 마세요.

## 추가 기능

- 비밀번호 로그인: 기본 비밀번호 `1222`
  - 서버 환경변수 `STOCK5_PASSWORD`가 있으면 그 값을 우선 사용합니다.
- 서버 공유 저장
  - Oracle: `data/stock5-0-state.json`
  - 한 컴퓨터에서 지정한 롱/숏 분류와 평균가가 다른 컴퓨터에서도 보입니다.
  - 로그인 후 10초마다 서버 상태를 다시 확인합니다.
- KOSPI100 / KOSDAQ100 / NASDAQ100 / Nikkei100 카드에 작은 버튼 추가
  - `입력`, `롱보유`, `롱관심`, `숏관심`, `숏보유`
  - 기본 배경은 모두 흰색
  - 네 상태 버튼은 동시에 하나만 선택 가능
  - 롱보유: 선택 시 빨강
  - 롱관심: 선택 시 반투명 빨강
  - 숏관심: 선택 시 반투명 파랑
  - 숏보유: 선택 시 파랑
- 롱보유/숏보유 선택 시 평균가 팝업
  - 평균가 저장 시 메인 캔들차트에 빨간 수평 점선 표시
  - 보유 버튼 또는 `입력`을 다시 눌러 수정 가능
  - 팝업의 `삭제`를 누르면 평균가와 수평선 제거
- NASDAQ/Nikkei 프리셋의 임시 이름을 Yahoo에서 영어 종목명으로 자동 조회
- `니케이 Top 50` -> `니케이100`
- Nikkei 프리셋을 100개 종목으로 확대

## GitHub에 수동 업로드할 파일

ZIP을 풀고 아래 경로를 그대로 유지해서 GitHub 저장소에 올리세요.

- `apply-stock5-0-update.mjs` (저장소 루트)
- `api/_state.js`
- `api/state.js`
- `api/name.js`

`data/`는 실제 사용자 데이터이므로 GitHub에 올리지 않습니다. 패치 실행 시 `.gitignore`에 `data/`가 자동 추가됩니다.

## Oracle에서 한 번에 반영

GitHub에 위 파일들을 올린 다음 Oracle에서 아래 한 줄을 실행합니다.

```bash
cd /var/www/stock5-0 && git fetch origin && git checkout origin/main -- apply-stock5-0-update.mjs api/_state.js api/state.js api/name.js && node apply-stock5-0-update.mjs && node --check scripts/server.js && npm install && npm run build && mkdir -p data && sudo systemctl restart stock5-0 && sudo nginx -t && sudo systemctl reload nginx && curl -I http://127.0.0.1:3050/
```

이 방식은 Oracle에 이미 있는 최신 `src/App.jsx`, `ChartColumn.jsx`, `server.js` 전체를 GitHub의 예전 버전으로 덮어쓰지 않고, 현재 파일에 필요한 변경만 적용합니다.

## 패치 후 GitHub에 완성본까지 반영하려면

Oracle에서 패치 적용 후 아래 파일들이 변경됩니다.

- `.gitignore`
- `scripts/server.js`
- `src/App.jsx`
- `src/components/ChartColumn.jsx`
- `src/index.css`
- `src/marketPresets.js`

기능 확인 후 이 6개 파일도 GitHub에 수동 업로드하면 GitHub 자체도 완성된 최신 소스가 됩니다. 새 API 3개 파일도 그대로 유지하세요.

## 공유 데이터 파일

Oracle의 실제 입력 데이터는 기본적으로 아래에 저장됩니다.

`/var/www/stock5-0/data/stock5-0-state.json`

서버 재시작이나 브라우저 변경으로 지워지지 않습니다. 소스 업데이트 때 `data/` 폴더를 삭제하지 마세요.
