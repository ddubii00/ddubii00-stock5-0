# stock5-0 종목 공유 기록

## 현재 버전 사용법

- 공통항목은 조건 1·2와 선택 가능한 조건 3을 처음부터 표시합니다. 조건 3의 기본값 `- (미포함)`은 서버에 전송하지 않으며, 지표를 선택하면 세 조건의 교집합을 찾습니다. 다시 `-`로 바꾸면 두 조건 검색으로 돌아갑니다. 조건 4~8도 추가할 수 있고 미포함으로 선택할 수 있습니다.
- 7·8·9·10·11번의 PER / F.PER / ROE / F.ROE / PBR / PEG / 시총 / 매출 / 영업이익 제목을 누르면 오름차순·내림차순으로 바뀝니다. 표시 반올림 전의 원본 숫자를 사용하고 0·음수를 정상 값으로 취급하며, 미제공/조회 실패는 양쪽 정렬 모두 마지막입니다. 페이지를 나누기 전 전체 필터 결과를 정렬하고 동일 값은 기존 순서를 유지합니다. 첫 정렬은 전체 결과 재무 조회 진행률을 표시하고 완료 후 순서를 적용합니다. 동시 2개 조회·기존 캐시를 공유하고 정렬하지 않을 때는 기존 지연 조회를 유지합니다. 금액은 표시 통화의 숫자 기준으로 정렬하며 통화 환산은 하지 않습니다. 11번의 롱·숏/준비·주의 분류는 유지하고 각 분류 안에서 정렬합니다. `정렬 해제`는 원래 목록 순서로 돌아갑니다. PER~PEG 열은 좁은 고정 폭으로 표시해 넓은 화면에서도 간격이 벌어지지 않게 합니다.

- `9. 골든/데드 크로스`: KOSPI·KOSDAQ·NASDAQ·일본 전체 종목의 5/20, 5/60, 20/60 종가 단순이평을 일/주 기준으로 비교합니다. 이전 단기≤장기, 최근 단기>장기면 골든, 이전 단기≥장기, 최근 단기<장기면 데드입니다. 최근 두 봉에서 새로 발생한 교차만 찾으며 최근 값이 같기만 하거나 기존 방향을 유지하면 제외합니다. 5/20은 최소 21개, 나머지는 최소 61개 봉이 필요합니다. 주봉은 실제 주간 마지막 종가를 쓰며 이번 주는 진행 중일 수 있습니다.
- `10. 공통항목`: 7·8·9번의 지표·일/주·방향·구름 종가/20이평·이평 조합을 조건별로 선택합니다. 2~8개 조건을 모두 만족하는 교집합(AND)만 시장+종목코드로 연결하며 동일 이름만으로 합치지 않습니다. 각 시장에서 조건별 최근 실제 거래일이 다르면 결과를 합치지 않고 준비/불일치 안내를 표시합니다. 일봉과 주봉을 섞어 선택할 수 있고 일치 조건·날짜, 공유 기록, 재무정보, 일/주 선택 네 차트 팝업을 제공합니다.
- `11. 종목들`: 기존 목록의 메뉴 번호만 9→11로 변경했습니다. `saved-stocks` 내부 키와 비밀번호·서버 기록·삭제·시장 필터는 유지합니다.
- 7·8·9번의 `일·주 엑셀 저장`은 화면의 봉 단위와 관계없이 **현재 시장·방향·종목명/코드 필터를 일봉과 주봉 양쪽에 적용해 한 파일로** 다운로드합니다. `일봉 요약`, `일봉 결과`, `주봉 요약`, `주봉 결과`의 네 시트로 구분하며 0건·검색 중·미완료·이전 자료도 각 시트에 명시합니다. 파일명에도 일봉+주봉, 각 검색 상태, 구름 종가/20이평 또는 이평 조합, 필터와 기준 거래일 범위를 넣습니다. 주봉 신호는 진행 중일 수 있습니다. 색상·숫자형 날짜/가격/비율·문자형 코드·전체 페이지를 보존하며 엑셀 생성/다운로드 중 서버 요청·파일 저장·업로드는 없습니다. 기존 6번은 현재 일/주 결과 저장을 유지합니다.
- 6·7·8·9·10번은 한 검색 작업과 종목당 같은 시세 자료를 공유하며 동시 조회는 최대 2개입니다. 일/주를 같은 응답에서 읽고, 공통조건도 같은 작업 상태에서 비교합니다. 일/주 전환·엑셀 저장·조건 수정으로 강제 전체 검색을 만들지 않습니다. 이전 v1~v5 캐시는 읽을 수 있으며 9·10번을 처음 열 때 교차 자료가 없는 종목만 보완해 v6로 저장합니다. 교차의 계산 가능 여부는 200주 이력 부족과 독립적입니다. 프런트엔드와 API 서버를 함께 업데이트하고 `data/` 공유 기록을 보존하세요.

- 구름돌파의 기본 검색은 `캔들 종가 기준`입니다(기준을 생략한 API 요청도 동일). 일반 구름에서는 **이전 봉 종가가 그 봉의 구름 안(경계 포함)이고 최근 봉 종가가 최근 구름 상단 초과/하단 미만인 경우** 돌파/하락으로 표시합니다. 장중 값은 제공처 최근 일봉/주봉 종가이며 지연될 수 있습니다. `20이평선 자체`는 별도 모드로, 종가가 아닌 20이평선의 위치만 판단합니다. 예를 들어 GS건설처럼 종가는 계속 구름 아래여도 20이평선이 새로 빠져나오면 20이평 모드에서만 표시될 수 있습니다.
- **두 봉 모두 선행1=선행2로 구름 두께가 0이면 선 교차도 검색**합니다. 각 봉의 선을 기준으로 이전 값이 아래(또는 선 위), 최근 값이 엄격하게 위면 돌파이며 반대면 하락입니다. 최근 값이 선에 닿기만 하거나 같은 쪽에 계속 있으면 제외합니다. 일/주 및 종가/20이평에 모두 적용하며 일반 구름 밖→밖 조건까지 넓히지는 않습니다. 저장된 구름 좌표에서 두 모드의 신호를 다시 계산하므로 이전 캐시에서도 즉시 반영하고 전체 재조회/공유 기록 삭제는 필요 없습니다.
- 국내 주봉 차트는 검색 일봉과 같은 네이버의 주봉 자료를 사용합니다. Yahoo 주봉의 UTC 일요일 날짜와 별도 최신 일봉이 함께 들어와 한 주가 두 봉으로 보이던 데이터 경로를 제거했습니다. 메인 캔들과 일목 요청은 종목별 같은 주봉 응답을 15초간 공유하고, 실패 시 다른 제공처로 몰래 바꾸지 않습니다. Express와 서버리스 모두 동일하게 적용합니다. DB손해보험 2026-10-30 실제 주봉 회귀 자료에서 이전 20이평 170,880/상단 176,200 → 최근 20이평 172,700/상단 172,425로 **275원 돌파**입니다. 수치가 실제 구름 안인 종목은 제외하되 이 종목을 임의로 제외하지 않습니다. 서버 업데이트 후 차트를 새로 열어 동일 기준으로 확인하세요.
- 구름 계산은 실제로 필요한 최근 79개 봉 중 선행 구름의 고가·저가 입력 구간만 검사합니다. 사용하지 않는 수년 전 가격 오류 때문에 종목 전체를 제외하지 않으며, 차트와 마찬가지로 제공처 수정주가/반올림 때문에 종가가 고가·저가보다 1~2단위 다른 경우 원본 값을 그대로 사용합니다(가격을 임의 보정하지 않음). 필요한 고가·저가가 미제공/역전/비정상이면 해당 일/주 계산에만 오류를 표시합니다. v4의 과도한 검사로 제외된 구름 결과만 자동 보완하고 기존 유효 검색/종목 기록은 유지합니다.

- `8. 구름돌파`를 추가하고 기존 종목 목록을 `11. 종목들`로 옮겼습니다. 기존 공유 비밀번호/기록/삭제 기능은 그대로 유지합니다.
- 구름돌파는 KOSPI·KOSDAQ·NASDAQ·도쿄 전체 시장을 일/주 단위로 검색합니다. 검색 기준에서 `캔들 종가 기준` 또는 `20이평선 자체`를 선택합니다. 일반 구름에서는 이전 봉의 해당 값이 그 봉의 일목 구름 안(경계 포함)에 있고 최근 값이 최근 구름 상단 초과면 돌파, 하단 미만이면 하락입니다. 이미 밖에서 움직이던 종목은 제외하되 위의 두께 0인 선 교차 조건은 포함합니다. 최근 값이 경계에 닿기만 한 경우는 제외합니다. 양운/음운을 모두 찾으며 캔들 꼬리의 고가·저가 접촉만으로는 판정하지 않습니다. 두 기준은 독립적으로 계산하고 기준 전환은 기존 구름 자료를 재사용하므로 추가 시장 검색/시세 조회가 없습니다.
- 일목 설정은 기존 차트와 동일한 9·26·52/26봉 선행이며 미래 구름이 아닌 해당 날짜에 실제 표시되는 구름과 비교합니다. 각 기간의 실제 고가·저가와 종가를 사용하고, 주봉 고가/저가는 주 전체를 집계합니다. 최소 79개 봉이 필요하며, 주봉 검색은 지난 완료 주봉과 현재 진행 중인 주봉을 비교하므로 장중/주중 결과가 바뀔 수 있습니다. 이력 부족·고가/저가 미제공·최근 거래일 불일치는 제외 사유로 표시합니다.
- 6·7·8번은 같은 작업과 동시 2개 제한, 일봉/추가 주봉 자료를 공유합니다. 이전 검색 캐시(v1~v4)는 유지하며 8번을 처음 열 때 구름 정보가 없거나 이전 버전의 과도한 검증으로 실패한 종목만 보완합니다. 구름돌파 목록도 시장/방향/종목 검색, 페이지 이동, 고정 종목명·헤더, 한 줄 재무정보, 롱·숏/준비/주의, 기존 네 차트 팝업과 주봉 연동을 지원합니다. 엑셀 다운로드는 6·7·8·9번에서 제공합니다. 업데이트 시 프런트엔드와 API 서버를 함께 반영하고 실제 `data/` 공유 기록을 보존하세요.

- 11번 각 행의 `주의!` 오른쪽 `삭제`는 해당 종목의 롱·숏/준비/주의 및 평균가를 한 번의 공유 서버 갱신으로 초기화합니다. 서버 성공 응답 후 목록에서 제거되며 다른 종목에는 영향을 주지 않습니다. 실패하면 행과 기존 선택을 유지하고 오류를 표시합니다. 삭제된 종목은 나중에 차트/6·7·8번에서 다시 선택해 기록할 수 있습니다.
- `준비! · 주의!만 표시한 종목`은 네 가지 롱·숏 상태를 선택하지 않고 준비 또는 주의가 켜진 종목만 포함합니다. 롱·숏+준비/주의를 함께 지정한 종목과 평균가만 남은 기록은 이 목록에서 제외합니다. 결과가 없어도 전용 목록과 0종목 안내를 표시합니다.
- 6·7번 결과 표에는 롱 보유 / 롱 관심 / 숏 관심 / 숏 보유 / 준비! / 주의! 버튼을 모두 제공합니다. 날짜 열은 `최근 비교일` 한 날짜만 표시합니다. 신호 계산에 필요한 이전 가격·이평과 기존 엑셀의 두 비교일은 변경하지 않습니다.

- 11번 목록의 `시장구분` 필터에서 모든 시장 / KOSPI / KOSDAQ / 미국(NASDAQ 등) / 일본 / 기타·시장 미확인을 선택할 수 있습니다. 기존 롱·숏 분류 필터와 종목명·코드 검색을 동시에 적용하며, 소제목의 종목 수는 현재 필터 기준입니다. 기존 기록은 변경하지 않고 `.KS`/`.KQ`/`.T` 등 저장 종목코드로 구분합니다. 미국 거래소 정보가 없는 기록을 NASDAQ으로 단정하지 않고 미국으로 묶으며, 시장을 확정할 수 없는 옛 코드는 기타로 표시합니다.

- `11. 종목들`은 기존 공유 기록을 롱 보유 / 롱 관심 / 숏 관심 / 숏 보유로 모아 보여줍니다. 분류 소제목은 빨강 / 반투명 빨강 / 반투명 파랑 / 파랑 글씨이며, 각 행에는 `준비!`·`주의!`·`삭제`와 재무정보를 표시합니다. 롱·숏 없이 준비/주의만 지정한 기록도 별도 목록에 표시합니다. 기존 비밀번호와 서버 기록을 그대로 사용하므로 다른 컴퓨터에서도 같은 기록을 읽을 수 있습니다. 종목명/코드 검색과 분류 필터를 지원합니다.

- 네 가지 롱·숏 상태는 한 번에 하나만 선택됩니다. 활성화된 버튼을 다시 누르면 해제됩니다.
- `주의!`는 기본 **꺼짐**입니다. 누르면 노란색으로 켜지고, 다시 누르면 꺼집니다. 롱·숏 상태와 독립적으로 저장됩니다.
- `준비!`는 `주의!` 바로 왼쪽에 표시되며 기본 꺼짐(흰색)입니다. 누르면 초록색 배경·흰색 글자로 켜지고 다시 누르면 꺼집니다. 롱·숏 및 `주의!`와 독립적인 `ready` 기록으로 서버에 저장되며 다른 기기에서도 같은 비밀번호로 접속하면 보입니다. 기존 기록에 이 값이 없으면 꺼짐으로 처리하며 기존 기록을 초기화하지 않습니다. 준비 기록만 있는 종목도 보관하고 모든 기록을 해제하면 삭제합니다. 배포 시 프런트엔드와 `/api/state` 서버를 함께 업데이트해야 합니다.
- 기록은 브라우저가 아니라 서버에 저장됩니다. 다른 컴퓨터에서도 같은 서버 비밀번호로 연결하면 기록이 보이며, 15초마다 또는 창에 다시 포커스할 때 갱신됩니다.
- 기존 분류와 평균가 데이터는 유지됩니다. 상태 변경은 해당 종목의 변경된 필드만 저장하므로 다른 기기에서 저장한 종목을 덮어쓰지 않습니다.
- Oracle은 기본 `data/stock5-0-state.json`을 사용합니다. `STOCK5_DATA_DIR`로 영구 저장 경로를 지정할 수 있습니다. 업데이트할 때 기존 `data/`를 삭제하지 마세요.
- 서버리스 배포는 영구 공유 저장을 위해 `KV_REST_API_URL`, `KV_REST_API_TOKEN`을 함께 설정해야 합니다.

이 기능은 이미 소스에 적용되어 있습니다. 최신 소스를 가져와 빌드하고 서비스를 재시작하면 됩니다. 아래의 예전 `apply-stock5-0-*.mjs` 패치 절차를 다시 실행하지 마세요.

## GitHub에 수동 업로드할 파일

ZIP을 풀고 아래 경로를 그대로 유지해서 GitHub 저장소에 올리세요.

- `apply-stock5-0-update.mjs` (저장소 루트)
- `api/_state.js`
- `api/state.js`
- `api/name.js`

`data/`는 실제 사용자 데이터이므로 GitHub에 올리지 않습니다. 패치 실행 시 `.gitignore`에 `data/`가 자동 추가됩니다.

## Oracle에서 한 번에 반영

GitHub에 위 파일들을 올린 다음 Oracle에서 아래 한 줄을 실행합니다.

```bash
cd /var/www/stock5-0 && git fetch origin && git checkout origin/main -- apply-stock5-0-update.mjs api/_state.js api/state.js api/name.js && node apply-stock5-0-update.mjs && node --check scripts/server.js && npm install && npm run build && mkdir -p data && sudo systemctl restart stock5-0 && sudo nginx -t && sudo systemctl reload nginx && curl -I http://127.0.0.1:3050/
```

이 방식은 Oracle에 이미 있는 최신 `src/App.jsx`, `ChartColumn.jsx`, `server.js` 전체를 GitHub의 예전 버전으로 덮어쓰지 않고, 현재 파일에 필요한 변경만 적용합니다.

## 패치 후 GitHub에 완성본까지 반영하려면

Oracle에서 패치 적용 후 아래 파일들이 변경됩니다.

- `.gitignore`
- `scripts/server.js`
- `src/App.jsx`
- `src/components/ChartColumn.jsx`
- `src/index.css`
- `src/marketPresets.js`

기능 확인 후 이 6개 파일도 GitHub에 수동 업로드하면 GitHub 자체도 완성된 최신 소스가 됩니다. 새 API 3개 파일도 그대로 유지하세요.

## 공유 데이터 파일

Oracle의 실제 입력 데이터는 기본적으로 아래에 저장됩니다.

`/var/www/stock5-0/data/stock5-0-state.json`

서버 재시작이나 브라우저 변경으로 지워지지 않습니다. 소스 업데이트 때 `data/` 폴더를 삭제하지 마세요.
